# 超能力ケモノ麻雀 — VRChat 多人数麻雀ワールド

> 🎬 **プレイ動画**：（ここに YouTube 等のリンク）
> 🌐 **ワールド**：「麻雀集会所 β」VRChat にてパブリック公開中（PC / Quest 対応・8卓・最大50人）

![ワールドのサムネイル](docs/images/ThumbnailWorld1.png)

![ポスター](docs/images/PosterLast.png)

VRChat 上で最大50人が同時に遊べる、雀魂（じゃんたま）準拠ルールの段位戦麻雀ワールドです。
麻雀の進行ロジックは市販アセット「青空麻雀」（スズ製作所）をベースに改造し、
その上に **マッチング・段位システム・演出・観戦中継・VR 操作・多言語対応** などを新たに開発しました。
開発は **AI エージェント（Claude Code）に実装を任せ、本人は企画・仕様・判断・検証を担う体制** で行っています（詳細は「担当範囲」）。

このリポジトリには **本プロジェクトで新規に作ったコードだけ**（青空麻雀に由来しないもの）を収録しています（Udon 実行時コード 54 ファイル／約4.2万行、Unity Editor 拡張 76 ファイル／約4.7万行）。

## このリポジトリについて（重要）

- 麻雀ロジック本体（`Mahjong.cs` ほか）は購入アセットであり、利用規約により改造版を含め再配布できないため **同梱していません**。
  そのため本リポジトリ単体ではコンパイルできません。コードを読んでいただくための抜粋です。
- 本体に加えた改修（同期まわりの不具合修正など）は、コードではなく下記「技術的な見どころ」で文章として説明しています。
- アート・サウンド・シェーダー等の購入アセットも同梱していません。
- 新規スクリプトも本体と同じ名前空間 `SuzuFactory.AozoraMahjong` に置いています（本体の型を直接参照するため）。
- 公開にあたり、スタッフの表示名などの個人情報は `<STAFF_NAME_1>` のような伏せ字に置き換えています。

## 技術スタック

- Unity 2022.3 / VRChat SDK3 Worlds / **UdonSharp**（C# サブセット → Udon VM）
- ターゲット：PC (Windows) と **Meta Quest（Android）**。性能は Quest 基準で設計
- ネットワーク：VRChat の同期変数（Manual Sync）＋ネットワークイベント。**専用サーバーなし・クライアント非信頼**
- 永続化：VRChat PlayerData（インスタンスをまたいだ段位・戦績・設定）

## 技術的な見どころ

### 1. サーバーの無い環境で「不正できない」対局を作る

VRChat には権威サーバーが無く、全員のクライアントが対等です。そこで卓ごとに **Owner（その卓の進行役になる1台）** を決め、
すべての操作を「プレイヤーは要求を送るだけ → 卓の Owner が送り主と合法性を検証 → 適用して全員へ同期」という流れに統一しました。
要求には送り主の照合をかけ、ネットワーク越しに呼べてはいけない処理は呼べない名前に変えています。

### 2. 「終局したはずの卓が、CPUだけで勝手に再開する」不具合の調査

本番で報告された再現性の低い不具合です。原因は **近接カリングで寝ていた端末が古い局面を持ったまま卓の Owner を引き継ぎ、その古い局面を全員に配っていた** ことでした。

- 対策：同期を1通でも受け取ったかで「局面が新しいか」を判定し、Owner 専用の処理は「Owner であるか」ではなく **「新しい局面を持つ Owner であるか」** で判定するように変更
- 古い Owner は配信せず、局面が新しい人（着席者を優先）に Owner を譲る。誰も引き取らなければ卓を空に戻す

性能対策（カリング）と同期の正しさがぶつかった例で、「性能のために寝かせた端末は情報が古い」という前提を設計に組み込み直しました。

### 3. Quest 基準の性能設計

- 8卓を **卓ごとに独立した Prefab** にし、同期の負荷を卓単位に閉じ込める
- 近くの卓だけを動かす近接カリング（`TableProximityCuller.cs`）
- 観戦カメラは描画するフレームだけ有効化（PC 30fps / Quest 15fps）
- 演出は RectTransform と α だけで動かし、毎フレームの更新は管理役1個に集約
- シェーダー変換・テクスチャ見直しで Quest 版を圧縮後 49MB（上限の約半分）に

### 4. 手作業をなくすための Editor ツール

8卓×多数の UI・演出・ボタンを手作業で配線すると、必ずどこかが漏れます。
そこで **Build（生成）→ Wire（配線）→ Validate（検証）** のメニューをすべての機能に用意し、
ワンクリックで全卓へ同じ構成を再生成し、参照の欠落を自動で検出できるようにしました（`Editor/` 以下）。
